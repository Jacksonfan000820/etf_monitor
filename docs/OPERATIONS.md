# 运行维护手册

## 每次变更或发布

1. 使用 Python 3.11/3.12 虚拟环境安装两份 requirements。
2. `python scripts/check.py`，记录提交、Python 版本、失败和跳过项。
3. `python scripts/offline_demo.py` 确认历史样本仍可解析。
4. 对真实来源只做受控 dry run，逐源检查状态、源日期、抓取时间和单位。退出码为 0 不等于所有源可用。
5. 核对最终提交的 Actions 结果；先以草稿 PR 审阅功能、配置与文档差异。
6. 真实发送、定时或部署须有对应授权、目标和验收记录，不从代码合并推导已上线。

## 运行产物

| 文件 | 内容 | 维护要求 |
| --- | --- | --- |
| etf_flows.db | ETF 历史与价格 | 私有保存、修改前备份，不提交 |
| /tmp/etf_db_*.html / png | ETF 可视报告 | 临时文件，需持久保留时人工复制 |
| market-digest/out/ | JSON / 文本日报 | 默认不提交；分享前核对内容许可及隐私 |
| 私有 X 导出 | 用户授权提供的记录 | 存私有目录，不放 Git、CI artifact 或公开 issue |

SQLite 备份应在脚本不运行时进行，或使用 SQLite backup API 获得一致快照。备份也包含历史数据，按同样权限保存。恢复时先在独立副本验证，不覆盖唯一原库。不要手工删除数据库来解决 schema 问题。

## 故障排查

- **测试依赖缺失**：用当前虚拟环境 `python -m pip` 安装两份 requirements；不要把日历 skip 当成功。
- **ETF unavailable / schema 错误**：检查源是否返回挑战页、字段变化或缺报；使用去敏的页面 fixture 建立回归。不要自动改成 0。
- **数据 stale / pending**：核对最近已收盘美国交易日以及缺报日期。北京时间早上并不保证所有基金已报齐。
- **新闻为空**：可能是时间窗口过滤、未知时间、源失败或配置为空，查看每个源的状态，不宣称“市场无新闻”。
- **截图失败**：安装 Chromium；先保留 HTML。浏览器安装并非解析测试前置条件。
- **飞书失败或结果不确定**：先在目标会话核对是否已收到，不盲重试；日志不得包含 webhook 或原始凭据。签名及其他能力以发送模块实际实现为准。
- **CI 绿但日报异常**：CI 主要验证离线逻辑；单源失败允许降级，仍需查看 report.json。生产调度、告警、去重和补跑不能假设已实现。

## 运维边界

不要运行两份写同一数据库的采集实例。依赖版本范围尚不是可复现 hash 锁；更新依赖后重跑全部测试。暂不承诺 SLO、连续运行、全天候告警或历史补齐。建议先稳定单源质量，再扩展覆盖与生产功能。
